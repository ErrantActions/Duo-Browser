# Duo Browser trust boundaries

This documents implemented policy, not a claim of independent security review
or complete resistance to WebKit/OS vulnerabilities.

## Ask Duo / Apple Intelligence boundary

Ask Duo uses Apple's on-device `SystemLanguageModel`; it has no OpenAI/Copilot
backend, API key, cloud fallback, or model-registered action tools. The browser
control opens a native sheet but does not read the page. A separate Read This Page
tap is required before a filtered preview is captured. Use This Excerpt
explicitly approves that snapshot; a separate Ask tap starts generation.
Private tabs block all chat. Error/start/loading pages and non-verified HTTPS
documents block page access, with only the exact bundled demo excepted. General
chat can work without a page; it starts with page access off, receives no page
data, and uses the text-only schema without navigation suggestions.

The reader is a fixed bundled script in a separate `WKContentWorld`, not code
generated by a model or supplied by the page. It skips forms, inputs, editable
regions, hidden elements and frames, does not access values/cookies/storage,
and bounds traversal, text and link count. Other visible page text can still
contain sensitive information; the user must review the preview. It is not a
general-purpose secret detector or a complete copy of the page.

Page text and link labels are untrusted model data. Prompt instructions are
not the only defense: native code accepts only bounded answer text and an
existing HTTPS link ID, and rejects navigation suggestions unless the user
allowed them. With suggestions off, the generated schema has no navigation field
at all. Answers are rendered as plain text, not actionable Markdown.
There is no arbitrary script, DOM click, form submission, purchase, or file
action. Full href and current-URL query metadata are omitted from the model
prompt; this does not remove URLs or private information already displayed
as visible text in the reviewed excerpt or link labels.

Every link opening, including a manual link from the preview, requires native
confirmation of the actual destination. The source tab, exact URL, navigation
generation, isolated document ID and continued link visibility are checked.
The parent rechecks the source after the assistant closes before issuing normal
HTTPS navigation. Website capability UI remains suspended while the assistant
is presented, even if the scene reactivates.

Context, questions and answers are memory-only. Six completed exchanges are
retained for display; only the last two shortened question/answer pairs enter
the prompt as untrusted JSON. Native link objects/hrefs are omitted from this
history, although text typed by the user or produced by the model can contain
URLs. Turning page access off discards both the excerpt and previous exchanges;
the model rejects a page-free request if page context has not been removed.
General chat has no live search or privileged tools, and its knowledge can be
outdated. Closing/backgrounding/tab
changes/navigation clear the UI and cancel work; operation tokens reject late
results. Timeout and API failures are explicit, not sample answers or silent
cloud fallbacks. Logs contain numeric error codes, not page text, questions,
answers or addresses. This first version provides reviewed excerpts and
confirmed navigation, not an unrestricted autonomous browsing agent.

Deterministic UI generation is an explicitly launched, visibly labeled DEBUG
test fixture, not a response fallback. Its generator is excluded from Release;
normal availability/error paths never select it. Native unit tests separately
probe the real Apple provider with public synthetic prompts. A simulator that
reports available but fails even the minimal plain-text probe is recorded as a
skip, not successful live inference; failures after a usable probe remain test
failures.

## Untrusted website boundary

Reading View is a separate local plain-text presentation, including in private
tabs. It does not execute copied HTML, fetch article images, or send content to
AI. Its parser bounds the source envelope, block count and text size and rejects
arbitrary file URLs. PDF export is an explicit user action; private tabs require
confirmation. PDFs contain host attribution rather than source query strings,
but article text itself may contain private information. Recipient apps can
retain their own copy. Protected, randomly scoped temporary exports are removed
when the share operation completes/cancels; audio stops on close/inactivity.
These controls do not promise prevention of a user's screenshots, recording,
intentional sharing, or complete filesystem cleanup after an OS/process crash.

- WebKit renders websites; no new rendering engine or certificate bypass exists.
- HTTPS main-frame origin is read from WebKit's frame/security-origin metadata
  and compared with the receiving web view's current origin. A message's claimed
  origin is never accepted. HTTP and iframes cannot access Duo capabilities.
- The sole file-origin exception is the exact bundled demo document. Entered
  file paths, file URLs elsewhere, data URLs, and executable URL schemes are
  not browser navigation targets.
- `WKScriptMessageHandlerWithReply` receives only a fixed versioned method
  catalog. Unknown fields/methods, malformed shapes, oversized messages,
  unsupported icons/control types, duplicate IDs, and wrong types are rejected.
- Envelope size is 32 KiB after JSON serialization. This bounds accepted
  configuration, not WebKit's underlying IPC allocation; a hostile page can
  still consume web-process resources. Payload nesting and collection counts
  are bounded. Rate is 20 requests per 10-second sliding window per tab.
- Websites supply only declarative values. There are no native selector,
  reflection, executable Swift, arbitrary file, URL-launch, clipboard, or
  unrestricted system-action methods.
- Native event data is JSON-encoded before JavaScript evaluation. Document IDs
  scope delivery so a subsequent SDK instance ignores a previous document's event.

## Authorization and lifecycle

Normal permissions are local decisions keyed by exact canonical HTTPS origin;
subdomains and ports are distinct. Defaults ask. Users can explicitly choose
different defaults in browser settings. Private tab decisions are not persisted.

Each tab owns its bridge, current panel, document ID, generation, limiter,
permission completion, and one-use native activation token. It cannot mutate
another tab's bridge. Every main navigation clears document-owned state.
Stored grants can reauthorize only a fresh valid configuration from the new
document. Pending permission/scanner work cannot complete against a different
navigation generation, origin, document ID, or tab.

Switching tabs/backgrounding dismisses camera work, settles pending permission
requests, cancels website dialogs, and pauses page media. Closing a tab also
removes message handlers/scripts and delegates. Weak proxies and captures avoid
retaining closed views through WebKit.

Revocation immediately clears matching panels, activation tokens, pending
permissions, and scans in open tabs. The OS Camera permission is separate and
must be changed in iOS Settings.

## Native interface

Native site controls use iPhone Duo's native system toolbar presentation on
iOS 27.1, or an explicitly opened sheet on older versions. They retain website attribution,
trusted browser Back/Refresh controls, and a Hide escape action. They do not
replace or configure the browser's address/navigation UI. Labels remain visible;
overflow scrolls vertically rather than disappearing. Configuration cannot hide
native escape UI or customize system permission prompts. Native symbols have
website-supplied accessible labels; the system may place toolbar items in its
normal overflow menu. The All Website Controls sheet keeps every non-spacer
control, its full label, and its badge available in a vertical scrolling layout.
Scanner permission/UI
is presented from the visible native container and cancelled when it closes;
origin, tab, and document authorization are unchanged. Page messages remain
explicitly website-labeled sheets, not disguised as iOS alerts.
The native edge bar's browser-owned **URL** button exposes the actual host and
connection state through its accessibility value and expanded editor. Sites
cannot replace it. Expanded editing
uses a local draft and the same URL scheme/search policy as the standard
address field; opening it cancels pending capability work and blocks new
website prompts until it is dismissed. The same URL button closes the bubble
on its second tap; no larger address sheet is presented. The draft is tab-local
and is not navigated or persisted merely by expanding it. An outside tap dismisses the
bubble instead of activating the webpage underneath it. No webpage is drawn underneath the
edge controls by disabling native safe areas. Only a noninteractive color
layer from WebKit's resolved background and the connected bubble's decorative
material extend behind the rail; webpage content and tap targets do not.

Optional confirmations identify the website. Appearance/accent choices are a
small catalog, not arbitrary native styling or images. VoiceOver labels and
minimum touch targets are provided; physical-device accessibility review is
still required.

## Detected site navigation

This is a browser feature, not a website capability grant. A fixed bundled
script runs in its own main-frame WKContentWorld. It reads visible anchor
labels/hrefs only in bounded semantic navigation/header candidates; it does not
read input values, cookies or storage, execute page-generated code, or hide
website elements. Ambiguity produces no shortcuts, not guessed actions.

Only verified HTTPS and the exact bundled demo are eligible. Cross-origin URLs,
credentials, script schemes, downloads, non-self targets and common
action/token queries are excluded. Native decoding rechecks all destinations.
These heuristics cannot prove that a website GET has no side effects; detected
controls are labeled as website links, not trusted browser commands.

Observation is coalesced and disabled for inactive/suppressed/off states.
Messages carry only document identity and URL and are accepted only from the
current isolated main frame. Before navigation, native and isolated checks
revalidate the source epoch/URL/document and continued primary-link membership.
Separate deadlines/cancellation tokens prevent delayed validations opening links
after a page/tab/policy change. Approved DuoKit controls always win.

Regular pin/hide choices persist SHA-256 route identifiers, not full destinations.
Private choices stay in the individual tab. Detection never grants DuoKit or
camera access and never triggers a scanner or model.

## Scanner

1. A user activates a visible native Duo control.
2. Native code issues a random, single-use token bound to the current bridge
   state, expiring after ten seconds.
3. The webpage explicitly requests scanning with that token and request ID.
4. Duo checks frame/origin/document/tab, consumes the token, and checks its
   separate per-origin scanner permission.
5. Supported hardware and ordinary iOS camera authorization are required.
6. VisionKit displays a live preview and cancel action. First result stops
   scanning; duplicate events are suppressed. Timeout is 60 seconds.
7. Outcome delivery rechecks document, generation, origin, and active tab.

No background scanning or automatic camera grant exists. No photos/video are
saved. Scanned strings are not logged, interpreted as URLs, persisted by Duo,
or forwarded elsewhere. Sites may process the values they explicitly receive.

### Browser-initiated field input

The separate **Scan Into Field** browser action requires an explicit native
launch and camera authorization, not a website API request. It does not grant
DuoKit permissions. A fixed main-frame helper in an isolated content world
remembers the last focused eligible input/textarea. The capture ticket is
single-use, expires after 75 seconds, and binds the exact element, source URL,
value, selection and form. Native code also checks tab/navigation identity,
foreground state and page-tool ownership. Backgrounding, closing or navigation
invalidates native work; generation and insertion have 15-second UI deadlines.
Canceled/late captures also clear their matching isolated ticket without
clearing a newer scan. An insertion must begin within five seconds of native
dispatch; the helper rechecks this deadline and visibility before Enter/submit.

Only verified HTTPS and the exact bundled demo are supported. Passwords and
autocomplete-marked payment/one-time-code inputs, hidden, disabled/read-only,
disconnected fields, iframes and contenteditable editors are excluded. Existing
field values stay in the isolated helper, not native preferences or logs. Codes
are bounded to 4 KB and never interpolated into executable JavaScript. Changed
targets and length violations fail without silently choosing another field.

Input emits cancellable beforeinput followed by input/change. Enter is disabled
by default. Enter Events is synthetic, not a hardware-trusted key. The separately
chosen Enter and Submit Form mode can perform a consequential website action:
it honors canceled Enter, uses requestSubmit and ordinary browser validation,
and restricts form targets to the same HTTPS origin/current tab or exact bundled
demo. It never clicks an arbitrary button. Sites with custom handlers should use
Enter Events to avoid requesting an additional standard form submission.
DuoKit result delivery remains separate: no typing/submission is added to it.
Compact sheets disable interaction with the page behind the camera.

## Other browser data and permissions

WebKit's normal permission prompts govern ordinary site media. A setting can
deny all website camera/microphone requests; otherwise Duo returns `.prompt`,
never an automatic grant. Location is subject to WebKit/iOS behavior. The Duo
scanner does not bypass camera permission via this website mechanism.

External app links use an allowlist and explicit native confirmation. Automatic
redirects/iframes cannot open other apps. Download destinations are constrained
to an app-controlled directory, with path components removed from suggested
names and UUID prefixes preventing collisions. Opening/sharing a downloaded
file is a separate user action. Names are limited by UTF-8 bytes, not character
count. Stored download paths must be single components matching their download
ID, and sharing rejects directories and symbolic links. Confirmed download
deletion refuses recursive directory removal and retains the record on errors.

Clear Browsing Data persists an empty session before awaiting cleanup, disables
new tabs, ignores callbacks to closed tabs, and waits for active transfers to
stop before removing WebKit website data. The replacement tab uses the local
start screen, even when a custom startup URL is configured, so cleanup does not
silently restart network activity. Bookmarks and completed files are retained.

Library files use atomic writes and iOS file protection. Failed reads do not
silently overwrite corrupt originals. Private website data is nonpersistent;
private history/tabs/decisions/download records are excluded from the library.
User-created bookmarks and explicitly downloaded files persist by design.
Favorites and Reading List entries are also explicit saved data and are shared
between regular/private sessions on this device. The native start page uses
local monograms, not remote favicon requests. Reading List does not fetch
articles in the background or promise offline copies.

Recently closed tabs retain regular page metadata in memory only. Private tabs
never enter that list, and clearing browsing data discards it. Page zoom stores
only a numeric per-tab preference and uses the existing WebKit instance.
Downloaded-file preview uses the same validated file location as sharing; it
does not expose a file-access method through DuoKit.

Structured native logs record only operational failures/codes, not URLs,
browsing content, or scanned values. The demo logs events visibly to its own
page, only in memory, and redacts native gesture tokens from that visible log.
UI tests do not deliberately print the full accessibility hierarchy into public
console logs. Test screenshots/result bundles can still contain the synthetic
demo page, so they remain local to the job and are not uploaded. CI must never
browse real accounts or production private data.
There is no analytics or synchronization service.

## Repository and release controls

- Signing/private-key files, local environment files, build output, user-specific
  IDE state, and downloaded test artifacts are excluded by the repository's
  ignore rules. Ignoring a file does not remove tracked history; scan both.
- Actions dependencies are pinned to immutable commit hashes and proposed
  updates are reviewed. Checkout credentials are not persisted.
- CI tokens have read-only contents permission. Unsigned pull-request jobs
  receive no Apple signing environment or signing secrets.
- Repository Actions permissions allow GitHub-owned actions only. Public
  repository secret scanning and push protection are enabled.
- Signing requires manual workflow confirmation on `main` and successful
  verification. The `app-store` environment retains its main-only restriction
  and disabled administrator bypass, but no second reviewer click is required
  by owner choice. Anyone granted repository write access must be trusted to
  start releases and control the code that receives signing secrets.
- Private signing values are removed from child-process environments before
  native archive tools execute. Temporary keychain/profile/API-key files are
  cleaned up even after failures. Both workflows are manual only on a documented
  standard public runner, with the Xcode release/SDK explicitly selected.
- Profile/certificate/app/entitlement validation and Apple build-history checks
  happen before native compilation. TestFlight runs all native unit tests once;
  slower UI automation remains in the separate full validation workflow.
  A successful owner-only beta upload is not a full UI acceptance claim.
- Optional artifacts contain whitelisted numeric test counts only, with one-day
  retention. No screenshots, raw result bundles/logs, app/IPA exports, or signing
  material are uploaded. Build numbers are checked against App Store Connect,
  not assumed safe from a reset repository workflow counter.
- Local agent/checkpoint refs are not publication branches. Never mirror-push
  local refs or publish local audit backups; they may contain workstation
  identity metadata that is not present in the public branch.

## Adding a native capability

1. Define a narrow versioned request schema; reject unknown fields and bound
   size, nesting, strings, arrays, and rate.
2. Reuse native frame/origin validation and per-tab document/generation checks.
3. Add a separate capability permission, revocation path, and iOS permission
   descriptions where required. Never infer system access from panel approval.
4. Require a fresh native activation token for sensitive actions. A field in
   website configuration or a forged DOM event is not evidence of user action.
5. Keep system actions and file paths under native control. Avoid arbitrary
   selectors, URLs, paths, or APIs exposed through generic dispatch.
6. Add visible native UI, cancellation, timeout, lifecycle cleanup, and a
   narrowly scoped result event. Do not return data after navigation/tab changes.
7. Test malformed messages, wrong origins/frames, replay, revoked permission,
   tab isolation, rate limits, and lifecycle races on a real WebKit instance.
8. Document the API, privacy impact, hardware limits, and fallback behavior.

## Remaining release work

Build/test verification, simulator browser acceptance, physical camera/privacy
flows, accessibility audit, privacy declaration review, app icon and signing,
storage migration/recovery, and an independent pre-release security review are
not replaced by this document or by passing unit tests.
